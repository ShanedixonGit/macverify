# Code of Conduct

## The short version

Be decent. Assume good faith. Argue about the code, not the person.

## Expected behaviour

- Be respectful and direct. Blunt technical feedback is fine; contempt is not.
- Accept that a change can be correct and still be declined, usually because it
  conflicts with one of the guarantees in [CONTRIBUTING.md](CONTRIBUTING.md).
- When you report a problem, give evidence. When you review one, read it first.

## Unacceptable behaviour

- Harassment, personal attacks, or discriminatory language of any kind.
- Publishing anyone's private information, including anything lifted from a
  `macverify` report.
- Deliberately filing misleading security reports, or using an issue thread to
  pressure rather than to inform.

## Security reports

Do not open a public issue for a vulnerability. Use GitHub's private advisory
flow, as described in [SECURITY.md](SECURITY.md).

## Enforcement

Report a problem privately to the maintainer through GitHub. Reports are handled
in confidence. The maintainer may edit, lock, or remove contributions, and may
block accounts, for behaviour that breaks these rules.

This is a small project with one maintainer and no paid support. Enforcement is
best-effort and the maintainer's judgement is final.
